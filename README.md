# skill-guide · 个人技能导航

**把任务变成可复核的技能选择与执行方案。**

安装了很多 Skills，却不确定该用哪个、是否需要组合，或怎样写调用 Prompt？`skill-guide` 根据任务和本地已有技能，推荐单个技能、互补组合或无需技能的方案，并写出执行 Prompt。你检查或修改后，再按确认的版本执行。

默认优先用 **本地 Skills + 本次任务 Prompt + 现有工具** 解决问题；只有存在关键能力缺口，或新增能力有明确价值时，才提出扩展建议。

## 快速开始

### 1. 安装

在具备 `skill-installer` 的 Codex 环境中，可以直接发送：

```text
请使用 $skill-installer，从 https://github.com/shepherd0106/skill-guide
安装 skill-guide 目录中的技能。
```

也可以下载本仓库，将内层的 [`skill-guide/`](https://github.com/shepherd0106/skill-guide/tree/main/skill-guide) 文件夹完整复制到当前环境的个人技能目录。请保留脚本、`agents/` 和 `references/`，不要只复制 `SKILL.md`。目录中已有同名技能时，先核对版本再更新。

索引助手需要 **Python 3.11+**，仅使用标准库，无需安装额外 Python 包。安装后，确认当前宿主已识别 `skill-guide`。

### 2. 描述任务

显式指定 `$skill-guide`，并尽量提供目标、材料和期望输出：

```text
请使用 $skill-guide，为下面的任务推荐合适的本地技能或直接处理方案。

目标：【要解决的问题】
材料：【文件位置、链接或已提供的内容】
交付：【期望输出及验收要求】
限制：【时间、环境、格式或操作范围；没有可省略】

先给出推荐理由和一版可执行的 Prompt，等我复核后再执行。
```

例如：

```text
请使用 $skill-guide。
我有三篇本地 PDF 论文，希望整理研究问题、方法、证据和局限，
输出一份中文对比笔记，每项结论注明来源。
先选择合适的本地技能并生成执行 Prompt，等我确认。
```

### 3. 复核后执行

导航会给出 **推荐方案、执行 Prompt、必要待确认事项**。Prompt 写清目标、材料、交付要求、实际技能名称及调用方式；组合方案还会写清执行顺序、阶段职责和交接成果。

| 你的回复 | 后续行为 |
| --- | --- |
| “确认执行”或“按这版执行” | 执行当前明确对应的方案 |
| 仅提出修改意见 | 更新 Prompt，等待复核 |
| “按以下修改版执行”并附修改内容 | 直接按修改版执行 |

显式调用导航后，即使推荐“无需 Skill”，也会先提交 Prompt 供复核。确认后会执行实际任务；只有目标、范围、技能组合或关键可用条件发生实质变化时，才重新提交受影响的部分。

## 如何选择 Skills

| 任务情况 | 推荐方式 |
| --- | --- |
| 普通能力和现有工具足够 | 说明无需 Skill，提供直接处理的 Prompt |
| 单个技能能满足主要交付要求 | 推荐一个首选技能 |
| 不同阶段需要不同的必要能力 | 推荐互补组合，明确各自职责 |
| 多个技能功能相似 | 选择一个首选；有真实取舍时提供少量替代项 |
| 本地方案存在关键缺口 | 说明缺口，提出有边界的扩展建议 |

选择依据包括任务适配、输入输出兼容性、当前可用条件、准备成本及用户已表达的偏好。局部差异优先用任务 Prompt 补足，避免叠加职责相同的技能。

用户指定的技能和产品会保留；不适用或不可用时，会说明原因与替代方案。某个技能没有被选中，不能据此认定它应当删除。

## 轻量索引与目录变化

每次新导航先检查当前技能目录，并维护一份“技能名称—功能描述—入口位置”的本地索引：

1. **增量刷新：** 检查已知目录及入口文件的变化，通常只重新读取变化的入口元数据。
2. **按需阅读：** 先检索少量候选，再阅读首选及必要替代项的完整说明；支持资源按需检查。
3. **执行前核验：** 复核所选技能的当前内容和配置，防止按过时说明执行。

首次建立索引、七天后首次调用，或手动要求完整刷新时，会校验全部入口。插件范围使用当前宿主提供的有效版本，避免把历史缓存版本当作现有技能。

默认缓存位于 `$CODEX_HOME/skills/.skill-guide-data/`；未设置 `CODEX_HOME` 时，位于 `~/.codex/skills/.skill-guide-data/`。缓存独立于技能包，仅保存技能元数据，不保存任务材料或聊天。可指定工作区内的可写缓存位置；缓存不可写或锁忙时，降级为内存刷新。

索引采用关键词检索，最终选择仍以技能说明和当前环境为准。零命中时会换词或查看简短清单；发现文件也不等于宿主已启用、工具和依赖已齐备。索引可以减少重复读取，实际耗时仍取决于目录规模、环境和任务复杂度。

详细命令、扫描范围及异常处理见 [索引操作说明](skill-guide/references/index.md)。

## 什么时候考虑新增技能

先尝试已有 Skill、Prompt、互补组合及现有工具。以下情况才值得提出升级：

- 关键要求通过本地方案无法合理满足。
- 新能力能明确减少大量重复操作，且检索、适配、安装、验证和维护成本值得承担。
- 稳定、反复出现的流程值得封装为可复用技能。

候选可以是现成 Skill，也可以是尚未封装的 GitHub 项目。会先核对能力与依赖，再提出直接使用、小范围适配或封装方案；未经验证的候选不会被标为可用。

外部检索、下载、安装或新增技能需要相应授权。缺少工具、依赖、数据或权限时，会单独说明；新增 Skill 不会自动补齐这些条件。具体规则见 [外部能力与封装说明](skill-guide/references/extension.md)。

## 触发与使用边界

需要稳定经过导航时，主动指定 `$skill-guide`。描述匹配可能自动触发，但不能保证每次专业任务都会先经过导航。

如果希望减少忘记调用的情况，可以在某次对话开始时增加局部约定：

```text
本次对话中，遇到需要先选择专业处理流程的任务，
请先使用 $skill-guide 生成方案和执行 Prompt，等我复核。
简单任务直接处理；补充材料、确认和继续执行沿用当前方案。
```

这是一种对话内约定，实际效果取决于宿主和上下文。技能自身不修改全局指引，不建立常驻进程，也不对每条消息额外运行导航。

导航方案遵守当前宿主指令、专业技能要求及用户授权。确认执行任务不会自动扩大安装、删除、发布或配置修改的范围。

## 仓库结构

```text
skill-guide/
├── SKILL.md                 # 导航规则与复核流程
├── agents/openai.yaml       # 宿主显示与调用元数据
├── scripts/skill_index.py   # 本地索引与候选检索
└── references/
    ├── index.md             # 索引命令、范围与降级处理
    └── extension.md         # 外部能力评估与封装边界
```

完整行为定义以 [`SKILL.md`](skill-guide/SKILL.md) 为准。使用者的索引缓存与个人偏好文件保留在本地，不随技能包发布。
