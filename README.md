# skill-guide · 个人技能导航

**简体中文** | [English](README.en.md)

**把任务变成可复核的技能选择与执行方案。**

安装了很多 Skills，却不确定该用哪个、是否需要组合，或怎样写调用 Prompt？`skill-guide` 根据任务和本地已有技能，推荐单个技能、互补组合或无需技能的方案，并写出执行 Prompt。你检查或修改后，再按确认的版本执行。

默认优先用 **本地 Skills + 本次任务 Prompt + 现有工具** 解决问题；只有存在关键能力缺口，或新增能力有明确价值时，才提出扩展建议。

每次推荐都会说明关键任务要求由什么能力负责、依据在哪里、还有什么待核验。你明确要求记住的选择习惯可以保存为有范围的本地偏好，下次同类任务再参考。

组合方案会进一步检查每个技能是否必要、前后阶段能否衔接。已确认或使用过的流程，可在你明确要求后保存，下次条件合适时生成新的待复核方案。

## 快速开始

### 1. 安装

在具备 `skill-installer` 的 Codex 环境中，可以直接发送：

```text
请使用 $skill-installer，从 https://github.com/shepherd0106/skill-guide
安装 skill-guide 目录中的技能。
```

也可以下载本仓库，将内层的 [`skill-guide/`](https://github.com/shepherd0106/skill-guide/tree/main/skill-guide) 文件夹完整复制到当前环境的个人技能目录。请保留脚本、`agents/` 和 `references/`，不要只复制 `SKILL.md`。目录中已有同名技能时，先核对版本再更新。

索引助手需要 **Python 3.11+**，仅使用标准库，无需安装额外 Python 包。安装后，确认当前宿主已识别 `skill-guide`。

### 2. 描述任务

显式指定 `$skill-guide`，并尽量提供目标、材料和期望输出：

```text
请使用 $skill-guide，为下面的任务推荐合适的本地技能或直接处理方案。

目标：【要解决的问题】
材料：【文件位置、链接或已提供的内容】
交付：【期望输出及验收要求】
限制：【时间、环境、格式或操作范围；没有可省略】

先给出推荐理由和一版可执行的 Prompt，等我复核后再执行。
```

例如：

```text
请使用 $skill-guide。
我有三篇本地 PDF 论文，希望整理研究问题、方法、证据和局限，
输出一份中文对比笔记，每项结论注明来源。
先选择合适的本地技能并生成执行 Prompt，等我确认。
```

### 3. 复核后执行

导航会给出 **推荐方案、关键对应关系、采用的偏好、执行 Prompt、必要待确认事项**；没有相关偏好时省略该项。Prompt 写清目标、材料、交付要求、实际技能名称及调用方式；组合方案还会写清执行顺序、阶段职责和交接成果。

| 你的回复 | 后续行为 |
| --- | --- |
| “确认执行”或“按这版执行” | 执行当前明确对应的方案 |
| 仅提出修改意见 | 更新 Prompt，等待复核 |
| “按以下修改版执行”并附修改内容 | 直接按修改版执行 |

显式调用导航后，即使推荐“无需 Skill”，也会先提交 Prompt 供复核。确认后会执行实际任务；只有目标、范围、技能组合或关键可用条件发生实质变化时，才重新提交受影响的部分。

## 如何选择 Skills

| 任务情况 | 推荐方式 |
| --- | --- |
| 普通能力和现有工具足够 | 说明无需 Skill，提供直接处理的 Prompt |
| 单个技能能满足主要交付要求 | 推荐一个首选技能 |
| 不同阶段需要不同的必要能力 | 推荐互补组合，明确各自职责 |
| 多个技能功能相似 | 选择一个首选；有真实取舍时提供少量替代项 |
| 本地方案存在关键缺口 | 说明缺口，提出有边界的扩展建议 |

选择依据包括任务适配、输入输出兼容性、当前可用条件、准备成本及用户已表达的偏好。局部差异优先用任务 Prompt 补足，避免叠加职责相同的技能。

用户指定的技能和产品会保留；不适用或不可用时，会说明原因与替代方案。某个技能没有被选中，不能据此认定它应当删除。

## 看得见的选择依据

推荐会把关键任务要求与技能、Prompt 或现有工具对应起来。简单任务用短句说明，复杂任务才展开表格：

| 任务要求 | 负责方式 | 依据 | 覆盖与待核验 |
| --- | --- | --- | --- |
| 阅读本地 PDF | 候选技能 A | 实际 SKILL.md 中的阅读章节 | 说明支持；工具条件待核验 |
| 比较方法、证据与局限 | A＋本次 Prompt | 阅读流程＋用户要求的比较维度 | Prompt 补充维度，执行后核对来源 |
| 中文 Markdown 笔记 | 本次 Prompt | 通用输出能力与格式要求 | 无需增加技能 |

表中的 A 是说明格式的示例，实际使用真实技能及已核对的出处。说明支持、条件待核验、已验证和未覆盖分别表达；不会把关键词命中、个人偏好或技能自述当作执行成功的证明。

相似技能只比较影响本次交付的差异；方案修订时，对应关系和执行 Prompt 一起更新。详细规则见 [对应关系说明](skill-guide/references/mapping.md)。

## 让组合可以检查，让流程可以复用

| 功能 | 具体做什么 | 使用时机 |
| --- | --- | --- |
| 组合必要性检查 | 逐个去掉技能，查看哪些关键要求或下游输入失去支持，精简重复职责 | 推荐多个技能时 |
| 阶段交接核验 | 比较输入输出格式、必需字段和来源要求；按需只读检查实际文件、JSON 顶层键或 CSV 表头 | 有阶段交接或明确验收要求时 |
| 经授权保存流程 | 保存已确认/使用流程的适用条件、阶段职责与文件指纹，同类任务核对后复用 | 你明确要求记住流程后 |
| 基于差异的关键追问 | 只有候选真实差异会改变方案时，问一个能决定选择的问题 | 缺失信息确实影响首选或组合时 |

例如，一份材料先由阅读技能提取来源与结论，再通过 Prompt 生成对比表：会检查阅读阶段是否提供后续所需字段，并解释为什么需要这个技能。如果普通 Prompt 已能满足交付要求，就精简组合。多个可删除候选逐个减少、重新检查，避免把互为备选的技能全部删除。

交接检查通过只说明相应结构条件满足，引用和结论仍需专业验收。检查依赖实际填写的对应关系与契约，不自动证明语义正确或方案最优。简单任务用短句完成判断，复杂方案才按需运行脚本，不为每条消息生成检查文件。详见 [组合与交接](skill-guide/references/composition.md)。

流程复用可以这样提出：

```text
记住刚才已完成的论文对比流程，仅用于本项目：输入 PDF，输出 Markdown，保留来源。
查看已保存的流程。
下次处理这组论文时，先检查有没有适用流程，再给出本次执行 Prompt。
停用论文对比流程；其他记录保留。
```

流程与偏好分别保存在本地 `workflows.json` 和 `preferences.json`。流程只保留通用摘要与必要条件，不保存完整 Prompt、聊天、任务材料或材料路径。当前要求和适用偏好优先；类型、条件不匹配就另选方案，条件未知或文件变化则检查受影响阶段，同名技能不自动替代。复用后仍需复核本次 Prompt；单次成功不会成为效果保证。

新导航先检查可复用流程，再展开新的候选比较。流程检索先排除已知条件冲突，每批默认最多核对 5 个候选；重复绑定只检查一次。有后续候选时会说明范围，必要时再查一批，避免把当前批次无可用项误认为没有适用流程。它不会自动学习、保存或执行新任务。详见 [流程复用](skill-guide/references/workflows.md)。

## 经授权记录的个人偏好

支持优先选择、尽量避免、明确排除，以及输出或流程偏好。规则可以限于某个项目或某类任务，例如：

```text
记住：论文精读任务优先考虑技能 A。
记住：这个项目的对比笔记默认使用 Markdown 表格。
查看我已保存的导航偏好。
停用刚才那条偏好；其他规则保留。
```

保存前会核对实际技能与适用范围；范围含糊时先提交具体规则。“这次用 A”只影响当前任务，“本次对话优先 A”只留在对话，单次失败不会自动转成长期排除。已有明确记录授权时直接完成并报告结果。

当前明确要求优先于历史偏好，项目规则优先于适用的个人规则；同级实质冲突交给用户复核。偏好可以补入候选，但候选仍须满足任务要求和实际条件。规则绑定具体技能路径，更新或迁移后检查相关变化，不自动转移到同名技能。

规则保存在本地 `preferences.json`，与索引独立；可查看、修改、停用和删除指定规则。只保存最小规则及简短理由，不保存完整聊天和任务材料，不随仓库发布。写入失败会明确报告并保留原文件。详细命令及范围匹配见 [偏好管理说明](skill-guide/references/preferences.md)。

## 轻量索引与目录变化

每次新导航先检查当前技能目录，并维护一份“技能名称—功能描述—入口位置”的本地索引：

1. **增量刷新：** 检查已知目录及入口文件的变化，通常只重新读取变化的入口元数据。
2. **流程优先、按需阅读：** 先检查已有流程，不能合理复用时再比较少量新候选；阅读拟用技能的完整说明，支持资源按需检查。
3. **执行前核验：** 复核所选技能的当前内容和配置，防止按过时说明执行。

首次建立索引、七天后首次调用，或手动要求完整刷新时，会校验全部入口。插件范围使用当前宿主提供的有效版本，避免把历史缓存版本当作现有技能。

默认缓存位于 `$CODEX_HOME/skills/.skill-guide-data/`；未设置 `CODEX_HOME` 时，位于 `~/.codex/skills/.skill-guide-data/`。缓存独立于技能包，仅保存技能元数据，不保存任务材料或聊天。可指定工作区内的可写缓存位置；缓存不可写或锁忙时，降级为内存刷新。

Python 或索引不可用时，可从当前宿主可见的少量技能继续选择，明确说明实际核对范围和待核验条件；不自动安装依赖，也不会把检索失败等同于没有适用技能。

索引采用关键词检索，最终选择仍以技能说明和当前环境为准。零命中时会换词或查看简短清单；发现文件也不等于宿主已启用、工具和依赖已齐备。索引可以减少重复读取，实际耗时仍取决于目录规模、环境和任务复杂度。

详细命令、扫描范围及异常处理见 [索引操作说明](skill-guide/references/index.md)。

## 什么时候考虑新增技能

先尝试已有 Skill、Prompt、互补组合及现有工具。以下情况才值得提出升级：

- 关键要求通过本地方案无法合理满足。
- 新能力能明确减少大量重复操作，且检索、适配、安装、验证和维护成本值得承担。
- 稳定、反复出现的流程值得封装为可复用技能。

候选可以是现成 Skill，也可以是尚未封装的 GitHub 项目。会先核对能力与依赖，再提出直接使用、小范围适配或封装方案；未经验证的候选不会被标为可用。

外部检索、下载、安装或新增技能需要相应授权。缺少工具、依赖、数据或权限时，会单独说明；新增 Skill 不会自动补齐这些条件。具体规则见 [外部能力与封装说明](skill-guide/references/extension.md)。

## 触发与使用边界

需要稳定经过导航时，主动指定 `$skill-guide`。描述匹配可能自动触发，但不能保证每次专业任务都会先经过导航。

适合“我不知道选哪个技能”“比较这些相似技能”“帮我安排技能组合”等选择请求。普通概念解释、日常改写通常直接处理；已选定专业技能或正在确认、继续已有方案时，沿用当前任务，不重新导航。

如果希望减少忘记调用的情况，可以在某次对话开始时增加局部约定：

```text
本次对话中，遇到需要先选择专业处理流程的任务，
请先使用 $skill-guide 生成方案和执行 Prompt，等我复核。
简单任务直接处理；补充材料、确认和继续执行沿用当前方案。
```

这是一种对话内约定，实际效果取决于宿主和上下文。技能自身不修改全局指引，不建立常驻进程，也不对每条消息额外运行导航。

导航方案遵守当前宿主指令、专业技能要求及用户授权。确认执行任务不会自动扩大安装、删除、发布或配置修改的范围。

## 仓库结构

```text
skill-guide/
├── SKILL.md                 # 导航规则与复核流程
├── agents/openai.yaml       # 宿主显示与调用元数据
├── scripts/skill_index.py   # 本地索引与候选检索
├── scripts/skill_preferences.py # 有范围的偏好管理
├── scripts/skill_plan.py    # 组合删除检查与只读产物检查
├── scripts/skill_workflows.py # 经授权保存与检索流程
└── references/
    ├── index.md             # 索引命令、范围与降级处理
    ├── mapping.md           # 任务要求与能力对应关系
    ├── preferences.md       # 偏好授权、范围与变更
    ├── composition.md       # 组合必要性、阶段契约与关键追问
    ├── workflows.md         # 流程记录、适用条件与复用
    └── extension.md         # 外部能力评估与封装边界
```

完整行为定义以 [`SKILL.md`](skill-guide/SKILL.md) 为准。使用者的索引缓存、个人偏好与流程记录保留在本地，不随技能包发布。

开发验证：在仓库根目录运行 `python -m unittest discover -s tests -p "test_*.py" -q`。测试检查脚本行为；另用 [导航行为验收案例](evals/navigation-cases.md) 检查选择、降级和复核边界。脚本测试或人工走查均不替代真实宿主触发测试与实际任务的内容验收。
