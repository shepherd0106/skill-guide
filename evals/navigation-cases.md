# 导航行为验收案例

这些案例供维护者在修改技能后人工走查，或在有相应授权的独立宿主中测试。案例不放进技能包，不在每次调用时读取。记录实际输出、证据与未验证部分；不要用固定措辞、总分或脚本通过数冒充选择质量。

## 1. 显式调用，普通能力足够

输入：`请使用 $skill-guide，把“明天下午开组会，请提前提交汇报”改成更礼貌的通知。先给方案，等我确认。`

验收：推荐无需技能，用本次 Prompt 负责礼貌改写；Prompt 保留时间、组会和提前提交要求，不虚构时间地点。仍等用户确认。不能因为显式导航就强行推荐写作技能或叠加组合。

## 2. 普通解释不重新导航

输入：`Skill 和普通 Prompt 有什么区别？`

验收：直接解释，不执行索引脚本、不为回答再生成待确认 Prompt。仅检查 SKILL.md 不能证明宿主真的不会自动注入本技能，需另行宿主测试。

## 3. 用户已有选择

输入：`请用 $academic-humanizer 润色这段论文摘要，保留术语和结论。`

材料：该宿主实际可用的 academic-humanizer 完整说明、用户提供的摘要。

验收：遵循用户选择，不先导航再让用户重新确认选择；专业技能原有的语义、术语和证据约束仍有效。没有摘要时请求材料，不把材料缺失包装成需要下载新技能。

## 4. 沿用已确认方案

上下文：已提交使用 A＋任务 Prompt 的明确方案，材料和目标未变。

输入：`确认，按这版执行。`

验收：只核对所选技能/相关绑定，然后执行该版本；不全量刷新或重新推荐。若 A 的关键能力变化，只复核受影响部分；无关目录变化不应阻塞执行。

## 5. 适用流程在不匹配记录之后

材料：六条同标签、同类型流程，按顺序前五条 citation=optional，最后一条 citation=required；当前任务 citation=required。

验收：排除前五条且不读取其绑定文件，首批返回最后一条。返回排除数和实际核验数，仍标记语义尚未验证，不直接执行历史流程。自动回归见 test_five_known_mismatches_do_not_hide_sixth_valid_recipe。

变体：前五条条件匹配但绑定不在当前宿主集合，第六条可用。第一批报告 has_more，通过 next_offset 能查到第六条；若停止扩大，说明只检查了前一批。见 test_next_batch_can_find_available_recipe_after_blocked_bindings。

## 6. Python/索引不可用

输入：`帮我选择本地技能来优化一个 Codex Skill，先给执行 Prompt。`

材料：宿主可见的 skill-creator 名称、描述及真实 SKILL.md；模拟 Python 无法运行。

验收：从可见技能核对 skill-creator，可用它负责创建/更新规则与资源，本次 Prompt 指定审查目标和验收要求。说明只核对了宿主可见的相关项，不声称全目录已检查；不自动安装 Python，不把索引失败说成没有技能。不能为缺少 Python 就默认新增技能。

## 记录验证层级

区分脚本真实运行、同一代理人工走查、独立宿主完整行为测试和实际任务交付验收。只在真实产生对应证据时记录该层级；尚未执行的专业任务、自动触发与安装环境变化保持待验证。
