# 个人技能导航

优先用已有 Skill、任务 Prompt 和现有工具形成合理方案。导航的产物是可复核的执行方案；用户确认后才执行任务。保持短入口、少量候选和按需读取。

## 入口与任务上下文

- 用户指定本技能、询问技能选择或需要先确定专业流程时使用。不对每条消息额外运行导航；确认、补充材料、进度询问和继续执行复用当前方案。
- 从对话提取目标、材料、输出、环境及限制，区分用户要求和待确认假设。只有缺失信息会改变选择或阻止执行时才提问；建议和待定假设不得冒充用户要求。
- 保留用户指定的技能和产品；若不适用或不可用，说明原因及替代方案，不静默替换。
- 不修改全局指引、不建立常驻进程。自动匹配不能保证触发，也不能保证所有专业任务先经过导航。

## 本地快速选择

1. 每轮新导航调用本技能的 `scripts/skill_index.py query`，一次完成增量刷新及候选检索。使用当前宿主提供的有效技能根目录补充 `--root`，尤其是插件当前版本；不要扫描插件缓存的所有版本。路径、命令与异常处理见 [索引操作](references/index.md)。
   从当前任务提取少量明确的任务标签，以 `--tag` 匹配适用偏好；检查查询返回的 `preferences`。若 `available_task_tags` 存在与当前任务同义的已保存标签，改用这些标签再查一次；不为命中偏好把无关标签附加到任务。当前明确选择覆盖历史规则时用已核对的 `--override-skill` ID。偏好缺失不阻塞导航，偏好损坏或读取失败必须说明未能应用，不能声称没有偏好。
2. 使用任务的能力、输入输出关键词检索；必要时补充英文同义词。脚本是字面检索助手，不是语义裁决者。候选太少时换一组关键词或读取简短清单，不能以零命中断定没有合适技能。通常先看 3–5 个候选，只为明确缺口扩展。
3. 结合索引与当前宿主技能元数据，阅读首选及必要替代项的完整 `SKILL.md`，核对输入输出、能力、环境和流程约束。读取说明是规划，不提前执行候选流程。资源文件和依赖只在会改变选择时检查。
4. 为关键任务要求建立“要求→技能/Prompt/工具→依据→覆盖或待核验”的对应关系；简单任务用短句，复杂任务才用表格。格式、证据状态和交接规则见 [对应关系](references/mapping.md)。每项关键要求必须有负责方式或明确缺口，修改方案时同步更新对应关系和 Prompt。
   多技能方案逐项检查“去掉它会失去什么关键支持”，检查前后阶段输入输出能否衔接；只在组合或交接存在疑问时读 [组合与交接](references/composition.md)，按需使用只读检查脚本。脚本不替代语义判断。
5. 找到满足主要交付要求、没有关键缺口、且无需大量重复操作或脆弱绕行的方案后停止扩展。索引仅辅助选择，实际文件、当前环境与上级指令为准。对应关系按当前任务生成，不预先读取全部正文或建立全量能力数据库。

选择规则：
- 普通能力足够时明确说无需 Skill；局部差异用本次 Prompt 或现有工具补足。
- 单个能完成就选单个。多个仅在提供不同必要能力时组合，写清顺序、交接成果和每个技能的职责。
- 功能相似者选一个首选；仅在存在真实取舍时给出 1–2 个替代项。不能因“都相关”重复叠加规划、润色或评审。
- 比较用户选择、任务适配、输出兼容、可用性、额外成本和用户已表达的偏好。不编造收益分数、置信度、使用历史或性能提升。
- 先核对必要要求和实际条件，再应用适用偏好：当前明确指令优先，项目规则优先于个人规则；同级实质冲突只复核冲突部分。偏好补入的候选仍须核对能力，不能因被偏好就认定适合；偏好只在相应范围生效，不授予外部操作权限。
- 条件接近时选择额外准备较少、已验证可用的方案，说明依据；只有明显改变结果、成本或操作范围的取舍才要求用户选择。
- 只有候选的真实差异会改变推荐时才问一个关键问题，说明答案如何对应不同方案；能从当前要求或适用偏好确定时直接使用。回答后更新对应关系与 Prompt，不给每个候选追加问卷，不用虚构收益或置信度引导选择。
- 若技能要求无法兼容，调整推荐并说明取舍；不自行改写原技能或忽略必要约束。不把未选中作为删除依据。

## 方案与执行 Prompt

默认输出简短的“推荐方案、关键对应关系、本次采用的偏好、执行 Prompt、必要待确认事项”，没有相关偏好时省略该项，复杂任务才展开。说明影响选择的偏好规则及编号；偏好不适用时解释关键原因。相似技能只比较影响本次交付的差异。方案说明具体能力，不预测无法证明的优势。

Prompt 必须包含已知目标、材料位置、交付与验收要求；使用经过核对的实际技能名称和当前宿主支持的调用形式。多技能增加阶段职责和交接；无需技能时写直接处理方式。只列会影响执行的环境条件、缺失材料与授权范围。不要再调用 skill-guide，不擅自加入安装、删除、发布或个人配置修改。

组合 Prompt 写明必要输入、交接格式、应保留的来源信息及检查点。格式兼容不代表内容正确；检查失败先在已确认范围内修复交接，关键能力或组合确需改变时只复核受影响部分。

写完后停在复核点，即使方案无需 Skill。说明用户可“确认执行”或“修改后执行”。

## 复核与执行

- “确认执行/按这版执行”授权当前清晰对应版本；只给修改意见则更新 Prompt 并等待；“按以下修改版执行”直接按修改版执行，不重复索要同一确认。
- 执行前用脚本 `check --id …` 只核验所选技能，并按需读取变化内容。目录无关变化不触发重新规划；关键能力、可用性或约束发生实质变化时更新受影响方案，请用户复核。
- 确认后执行真实任务，不停在再次推荐。不把常规实施细节视为重新确认理由；实质改变目标、范围或组合才重新提交受影响部分。
- 遵守专业技能必要流程、当前权限和用户授权。任务确认不扩大外部操作范围；导航方案不得覆盖上级指令。
- 遇到失败先做范围内的合理修复；没有明确进展时说明障碍及下一步，不反复重试或静默引入新技能。

## 偏好与反馈

- 仅要求查看或变更偏好时直接处理偏好管理，不生成额外的任务执行 Prompt 或运行无关导航；绑定技能时才按需检索和检查入口。清晰的变更指令已有授权即可实施，范围含糊时只复核待保存规则。
- “这次用 A”仅影响当前任务；“本次对话优先 A”仅留在对话。“记住/以后这类任务优先 A”等明确持久化要求可记录；范围含糊时提出具体待保存规则供复核，已有清楚授权不重复询问。创建偏好功能的授权不等于自动保存每条反馈。
- 仅维护 `prefer`（优先）、`avoid`（尽量避免）、`exclude`（明确排除）、`prompt`（输出或流程）规则。保存最小规则和简短理由，任务材料、完整聊天和单次失败日志不写入偏好；“这次失败”不会自动成为长期排除。
- 处理持久化要求、偏好冲突或绑定变化时读 [偏好管理](references/preferences.md)。使用 `scripts/skill_preferences.py` 查看、应用/修改、停用/启用或删除指定规则；变更前有相应用户授权才传 `--authorized`。报告实际写入结果；不可写时保留原文件，不改权限或另建副本，不声称已经记住。
- 按精确技能 ID/路径绑定，不能只按同名转移；`changed/needs_review` 需检查相关能力，`missing/out_of_scope/disabled` 需说明条件。普通更新不自动取消排除，也不自动改写偏好；对象或适用含义实质改变时才请用户复核并按授权更新。未找到原技能时保留规则，不阻塞其他合理方案。

## 经授权保存的流程

- 每轮新导航在索引刷新后只读查看已有流程；没有记录就继续普通选择，不创建文件。流程候选按任务标签、输入输出类型、硬约束和环境条件筛选，只核对少量匹配流程绑定的技能与相关资源。具体命令与状态见 [流程复用](references/workflows.md)。
- 流程是待复核的模板；当前用户要求与适用偏好优先。条件不匹配则放弃本次复用，条件未知或文件变化则核对受影响阶段；不为套用旧流程放宽要求，也不按同名技能重绑定。找到可复用流程后替换本次材料与参数，仍提交执行 Prompt 等待确认。
- 仅在用户明确要求“记住/更新这个流程”时保存已确认或实际使用过的版本；记录任务类别、适用条件、阶段职责、技能及相关文件指纹、已检查事项与局限。确认过与执行过分开表达；单次成功不证明未来效果。
- `scripts/skill_workflows.py` 独立维护 `workflows.json`，可查看、更新、停用/启用、删除指定记录。与偏好相同，清晰的持久化指令已提供授权，含糊时仅复核待保存内容；不保存完整 Prompt、聊天、材料内容、材料路径或失败日志，不自动学习、不自动执行。
- 仅管理流程的请求直接处理，不额外生成任务 Prompt；写入失败保留原记录并报告，不另存到未授权位置。历史记录不授予工具、外部操作或安装权限。

## 能力缺口与升级

默认不联网，不自动安装。依次考虑已有 Skill＋Prompt、互补组合、现有工具或小范围适配。区别缺少流程指导、工具、依赖、数据和权限；新增 Skill 不自动补齐后三者。

仅在关键要求无法合理满足，或新能力能明确减少大量重复工作且准备成本值得承担，或反复出现的稳定流程值得封装时提出升级。把检索、适配、安装、验证和维护成本一并考虑。“更专业/也许更好”不足以新增。

需要升级时才读 [外部能力与封装](references/extension.md)，提交具体缺口和有边界的调查或实施 Prompt；等待授权。候选可为现成 Skill 或普通项目，未经验证不得标为可用。仅调查获批时不得扩大到安装；索引和偏好更新不等于修改其他技能。
