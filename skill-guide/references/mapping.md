# 任务要求与能力对应关系

本说明用于新导航及实质修订方案。只处理会影响选择和验收的要求，通常直接复用候选阅读，不增加全部技能正文扫描。对应关系默认留在当前对话，用户要求保存方案时才写文件。

## 建立依据

1. 从用户要求提取必要输入、处理、交付和限制；对假设明确标注，不把建议升级为硬要求。
2. 将每项关键要求交给实际技能、Prompt 或现有工具。未覆盖项明确为缺口，不能遗漏或用笼统“综合处理”代替。
3. 技能能力依据完整 `SKILL.md` 的实际章节，涉及具体脚本行为才检查对应脚本。引用文件及章节；行号仅在实际核对后给出。描述关键词命中和偏好只负责发现候选，不能证明覆盖。
4. 区分下列状态，不为所有要求重复跑验证。依赖、工具和材料只在影响方案时检查；执行后再核对真实交付。

| 状态 | 表达方式 |
| --- | --- |
| 说明支持 | 实际说明明确包含相关流程；尚未运行验证 |
| 需补充指导 | 已有处理能力，本次 Prompt 补充维度、格式或验收要求 |
| 条件待核验 | 工具、依赖、输入或权限尚未确认，说明影响及核验时机 |
| 已验证 | 指明真实检查或运行及其适用范围，不泛化为全任务成功 |
| 未覆盖 | 写清关键缺口及直接处理、替代或扩展方式 |

Prompt 可以补足组织和表达要求，不能凭文本补齐缺少的程序、数据或权限。通用模型能力/现有工具可负责的部分直接写明，不虚构技能出处。

## 展示

简单任务用一句或数句，复杂任务用表格。无需技能的方案也简短说明要求如何由普通能力和工具满足。示例中的 A 为占位候选，实际使用真实名称及已核对的出处。

| 任务要求 | 负责方式 | 依据 | 覆盖与待核验 |
| --- | --- | --- | --- |
| 阅读本地 PDF | A | A 的 SKILL.md → PDF 阅读章节 | 说明支持；当前读取工具待核验 |
| 比较证据与局限 | A＋本次 Prompt | 阅读流程＋用户要求的比较维度 | 需补充指导；执行后核对来源 |
| 中文 Markdown 交付 | 本次 Prompt | 通用输出能力＋用户指定格式 | 无需增加技能 |

比较相似技能时，只列影响当前交付的实际差异；有出处才说明优势。没有真实差异时用已授权偏好或较少准备成本选择，不编造评分。多个技能时写明各阶段职责、交接输出、必要输入条件；相同职责避免重复。

执行 Prompt 使用与表格一致的技能、材料、验收和范围。用户修改目标或方案后同步更新两者。执行前所选技能有变化时，仅检查受影响要求；发现实质缺口时复核受影响方案。
